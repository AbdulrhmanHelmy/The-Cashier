# Offline five-day trial

The existing RSA signed, device-bound perpetual license remains the first authority. A valid permanent license permits access even if trial artifacts are expired, missing, or inconsistent. No issuer key or signing endpoint is shipped with the POS.

Without a permanent license or previous trial, startup opens the **existing native `ActivationForm`**. It retains the device request code, copy action, signed-license input and permanent activation. Eligible devices also see `ابدأ التجربة المجانية — 5 أيام`. Starting is explicit and uses the trial security service; the button is absent after a trial starts or ends. The trial lasts exactly 120 continuous hours from its UTC start, including time when the app is closed.

The native expired/invalidated dialog displays the approved Arabic data-safety copy and exactly two main actions: `التواصل للتفعيل` and `الذهاب لشاشة التفعيل`. The latter opens the same existing `ActivationForm`. The former opens a compact RTL contact dialog with the official numbers **01157999456** and **01273266695**, each with a copy button. These numbers are defined once in `ActivationSupport`; no environment variable or WhatsApp assumption is needed. The activation form also links to this contact dialog. All three native forms use the Windows app light/dark preference where available and fall back to light on older systems.

## Storage and recovery

Current installations also write `%ProgramData%\AlKhayal\Security\TrialState.bin` as a fourth, machine-wide consistency witness outside the business database and normal backup. It contains the same DPAPI LocalMachine-protected versioned record as the three legacy stores. The directory ACL grants SYSTEM and Administrators full control and authenticated users modify access so an unprivileged POS can update it across Windows accounts. This protects against accidental damage and simple profile/database deletion; a local user can still replace it or invoke DPAPI, so it is not a trusted anti-rollback authority. Files are written through a flushed temporary file and atomic replacement. The security witness is written first; a crash may leave it one revision ahead, which the existing reconciliation accepts. A missing fourth file with valid legacy records is created from the original start and expiry without granting new time. A valid permanent license is checked first and remains effective regardless of trial-file state.

`TrialState.bin.events` is a bounded 128-entry event log in the same directory. Entries contain UTC timestamps, event codes, trial ID, and revision, protected with machine DPAPI and linked by SHA-256. It records trial start, state load, checkpoints, expiration, invalidation reasons including rollback and device mismatch, recovery/migration, and recognition of a valid permanent license. Broken event integrity denies trial access without a valid permanent license. Rotation starts a new local chain, so the log is diagnostic evidence rather than an external rollback anchor. A surviving event log prevents an all-record deletion from appearing eligible; deleting the log and all four records still permits a fresh trial. The log does not contain license secrets or raw hardware identifiers.

The three legacy layers contain the same versioned logical record: ID, hardware request fingerprint, start, exact expiry, last accepted UTC time, highest observed UTC time, state, and increasing revision. The database stores the fields and a protected integrity envelope in `TrialState` (migration `090_trial_licensing.sql`). The file is `%LOCALAPPDATA%\AlKhayal\Licensing\trial.dat`; this owner-profile path avoids the existing administrator-only permanent-license directory in ProgramData. The Registry location is `HKCU\Software\AlKhayal\Licensing\TrialState`. File and Registry values are versioned text envelopes containing Windows DPAPI LocalMachine-protected records. Local profile ACLs protect the file from other standard users; DPAPI protects record authenticity against casual editing. The business database is not deleted or reset by licensing.

Each checkpoint atomically replaces the ProgramData witness, writes SQLite transactionally, replaces the profile file atomically, then writes Registry. A process mutex serializes trial checks within the Windows session; cross-session serialization still needs deployment verification. If a crash interrupts a write, only a matching record at the immediately preceding revision is accepted and all four stores are advanced from the highest authenticated record. One missing layer is reconstructed from surviving authenticated records. A conflicting trial ID, device, start/expiry, status, future field, or revision more than one behind invalidates the trial. Corrupt protected content also invalidates and attempts to persist the invalidated state. Repeated normal requests checkpoint at most once per minute; expiry and repair checkpoint immediately. No missing artifact starts a trial automatically.

## Clock and access

The service compares UTC wall time with the highest stored observation and a running-process monotonic `Stopwatch`. A backward move greater than two minutes invalidates the trial. Smaller corrections cannot move the trusted observation backward. At exactly the stored expiration instant the trial becomes `Expired`; moving the clock forward past it also expires it. Expired and invalidated states do not restart from the UI. A new permanent license can be installed at any time.

The desktop checks on startup, focus and a one-minute timer. The OWIN middleware and direct Web API handler check on each request, so an already open WebView2 page or session cannot bypass expiry. Requests already admitted before expiry finish at their existing transactional boundary; no sales posting logic changes. The active desktop shows a small keyboard-focusable countdown link to the existing activation form.

After the activation dialog closes successfully, startup recreates the splash before preparing the main shell. This applies both to a newly started trial and a newly installed permanent license; the dialog had closed the original splash before returning.

## Limits and operations

A separate user profile has separate file and HKCU records, but the shared local business database remains another record; LAN deployments need an explicit server-side trial path and identity review. A full OS image rollback, deleting every artifact, administrator control, and manipulation entirely while powered off cannot be prevented by an offline design. Windows 7 SP1 and Chromium 109 remain unqualified deployment targets until tested on the actual runtime.

Tests use fake UTC/elapsed clocks and temporary SQLite files/Registry keys. They cover the exact 120-hour boundary, rollback, forward jumps, permanent precedence, missing layers, corrupt file, interrupted single revision, old replay, direct HTTP denial, and restart. Native UI tests cover trial eligibility, one-time start, exact expired actions, contact-number copying, activation after expiry, RTL and both palettes. Production trial files, Registry values, and operational data are not used by tests.

The isolated `TrialToPermanentPersistenceTests` integration cases also start a real Windows-backed trial, save a marker in the same SQLite business database, reject a correctly signed license for another device without changing trial expiry, install a disposable RSA-signed license either during the trial or at the exact expiry, and reconstruct both licensing services. They assert permanent access, unchanged trial state, byte-identical license storage, and retained business data after reconstruction. They do not exercise the real UAC helper or production owner key.
