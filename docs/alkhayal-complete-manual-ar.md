# الدليل الشامل لنظام الخيال POS — كتالوج الاستخدام والاختبار اليدوي

> **نسخة مرجعية مبنية على الكود — 7 نوفمبر 2026.** هذا الدليل مخصص لقاعدة اختبار منفصلة، وليس لبيانات عميل حقيقية. مصدر الحقيقة هو `frontend/data/screens.json` والـrenderers والـAPI وخدمات Application وطبقة SQLite والاختبارات الموجودة وقت إعداد الدليل. وجود مسار في السجل لا يعني أن عملياته محفوظة؛ كل حد معروف مذكور أدناه.

## 1. طريقة استعمال الدليل وحالة النظام الحقيقية

الخيال نظام نقاط بيع وإدارة تشغيل عربي، يعمل كتطبيق Windows بواجهة HTML داخل WebView2، ويستعمل نفس واجهة HTTP عند فتحه من متصفح مصرح. البيانات الحقيقية المحفوظة تشمل الدخول والمستخدمين والصلاحيات والإعدادات والمنتجات والعملاء والموردين والمخزون والمشتريات والمبيعات والمرتجعات والخزينة والمصروفات والموظفين والطباعة والتقارير والنسخ الاحتياطي. توجد شاشات توافق قديمة تحوّل إلى شاشة أحدث، وشاشات غير منفذة، كما أن واجهتي التقسيط موسومتان في السجل نفسه بأن الإنشاء والسداد محاكاة داخل الجلسة؛ لا تعتبرهما إثباتًا ماليًا دائمًا قبل الاختبار اليدوي.

### رموز الحالة

| الرمز | المعنى العملي |
|---|---|
| منفذة | لها renderer حقيقي ومسار عمل؛ يلزم اختبار بصري وفعلي |
| تحويل | الرابط القديم يفتح شاشة أخرى ولا يملك عملية مستقلة |
| جزئية/جلسة | واجهة موجودة لكن جزءًا من أثرها غير دائم أو يحتاج تحققًا |
| غير منفذة | نموذج عرض/تقرير قديم أو ميزة مؤجلة |
| مشروطة | لا تظهر إلا عند تفعيل `featureKey` ومنح الصلاحية |
| إداري | لا يفتحها الكاشير حتى لو عرف الرابط |

## 2. تجهيز بيئة تجربة آمنة

1. استخدم تثبيتًا وقاعدة SQLite مخصصين للاختبار، ولا تنسخ قاعدة العميل إلى جهاز غير مؤمَّن.
2. سجّل المسار المعروض في **الإعدادات ← البيانات والصيانة**، وأنشئ نسخة يدوية قبل أي رحلة مترابطة.
3. لا تختبر الاستعادة إلا على قاعدة قابلة للاستبدال؛ الاستعادة تستبدل بيانات العمل الحالية وتُخرج الجلسات، لكنها لا تنقل الترخيص أو مدة التجربة.
4. جهّز طابعة/ماسح/ميزان فعليًا فقط لسيناريوهات الأجهزة؛ نتيجة الإرسال للطابعة لا تثبت خروج ورق صحيح.
5. استخدم بيانات وهمية ثابتة: منشأة «بقالة النيل التجريبية»، عميل «أحمد التجريبي» هاتف `01000000001`، مورد «شركة النور التجريبية»، صنف «أرز مصري 1 كجم»، كود `RICE-001`، شراء 20.00، بيع 25.00.

## 3. التشغيل والتفعيل والدخول

### التشغيل لأول مرة

يشغّل تطبيق Windows الخادم المحلي ثم WebView2 على `127.0.0.1:5137` افتراضيًا. عند غياب WebView2 أو تعذر الخادم تظهر شاشة خطأ عربية مع إعادة المحاولة/الإغلاق، ولا يُحذف ملف البيانات. أول قاعدة بلا مستخدم تسمح بإنشاء مسؤول واحد؛ بعدها يُغلق bootstrap. كلمات المرور أي نص غير فارغ حسب السياسة الحالية، مع توصية عملية بكلمة قوية.

### التفعيل والتجربة

- عند عدم وجود ترخيص دائم صالح تظهر نافذة الوصول: بدء تجربة خمسة أيام إن كان الجهاز مؤهلًا، أو إدخال الترخيص الصادر لهذا الجهاز.
- انسخ **كود طلب الجهاز** وأرسله للدعم، ثم الصق الترخيص الموقّع. لا تنشر مفاتيح المُصدر أو ملفات الترخيص الداخلية.
- انتهاء الخمسة أيام يمنع الوصول التشغيلي ويعيد نافذة التفعيل. النسخ الاحتياطي لا يحتوي ترخيصًا ولا `TrialState` ولا الجلسات.

### سيناريوهات الدخول والتفعيل

**TC-ACT-001 — بدء التجربة:** على تثبيت اختباري مؤهل، اختر بدء التجربة، تحقق من فتح الدخول وظهور الأيام المتبقية بعد إعادة التشغيل. سلبي: غيّر ساعة الجهاز للخلف وتأكد أن النظام لا يمنح مدة إضافية.  
**TC-ACT-002 — التفعيل الدائم:** اعرض كود الجهاز، أدخل ترخيصًا صحيحًا صادرًا له، أعد التشغيل وتحقق من عدم ظهور بوابة التجربة. سلبي: ترخيص جهاز آخر/نص تالف يجب رفضه بلا تغيير البيانات.  
**TC-AUT-001 — إنشاء أول مسؤول:** أدخل اسمًا واسم مستخدم وكلمتي مرور متطابقتين؛ يجب إنشاء حساب واحد وتسجيل الدخول. سلبي: عدم التطابق أو حقل فارغ لا يترك مستخدمًا جزئيًا.  
**TC-AUT-002 — الدخول والخروج:** أدخل بيانات صحيحة، تحقق من اسم المستخدم والواجهة، ثم **تسجيل الخروج** وتأكد من الرجوع إلى `login.html`. بيانات خاطئة/حساب معطل يجب ألا تنشئ جلسة.

## 4. الواجهة والتنقل

- الشريط الجانبي يعرض الوحدات المتاحة وفق الميزة والصلاحية. عند عرض ضيق يتحول إلى شريط أيقونات 64px؛ اختيار الأيقونة يفتح قائمة الوحدة.
- **الوصول السريع**: الكاشير اللمسي، إضافة سريعة للأصناف، المرتجعات، سند صرف، البيع بالتقسيط، التنبيهات؛ العنصر غير المتاح لا يظهر.
- كل شاشة تفتح تبويب مساحة عمل؛ اضغط `×` للإغلاق، والصفحة الرئيسية لا تُغلق. زر الرجوع يعود ضمن سجل التنقل.
- البحث العام يبحث عناوين ووصف الشاشات المسموحة فقط، بحد أقصى عشر نتائج. لا يبحث سجلات العملاء/الأصناف.
- إشعار «بيانات الصفحة اتغيرت» يعني أن snapshot تغير؛ اضغط **تحديث البيانات** قبل القرار أو الحفظ.
- النوافذ المنبثقة تحبس التركيز؛ **إلغاء** أو `Esc` يغلقانها إن لم تكن عملية حفظ جارية. التأكيد الخطر لا يتم إلا بالزر الصريح.
- المظهر فاتح/داكن/النظام محفوظ على الجهاز، وكذلك طي القائمة؛ البيانات التجارية لا تحفظ في localStorage.

| الاختصار | الوظيفة |
|---|---|
| F1 | اختصارات لوحة المفاتيح |
| F3 | الكاشير اللمسي |
| F10 | إدارة الوردية |
| Ctrl+K | البحث العام |
| Esc | إغلاق النافذة النشطة |
| F2 في POS | بحث الصنف/الباركود |
| F4 في POS | اختيار العميل |
| F6 في POS | فاتورة جديدة |
| F8 في POS | إتمام البيع |
| F9 في POS | طريقة الدفع |

**TC-NAV-001:** افتح ثلاث شاشات من الشريط والبحث والوصول السريع، بدّل وأغلق التبويبات، وضيّق النافذة. المتوقع بقاء تمرير مساحة العمل منفردًا، وعدم ظهور شاشة ممنوعة.  
**TC-NAV-002:** جرّب كل اختصار خارج حقل كتابة وداخله؛ داخل الحقول لا ينبغي أن يسرق F1/F3/F10 الحدث، وماسح الباركود يعمل في POS فقط.

## 5. الإعداد الأولي والإدارة

### بيانات المنشأة والإعدادات العامة والمظهر

من **الإعدادات** افتح **بيانات المنشأة** وأدخل الاسم والعنوان والهاتف والبيانات الاختيارية وتذييل المستند، ثم **حفظ**. في **الإعدادات العامة** اضبط التاريخ والوقت، فواصل الأرقام، العملة، المنازل العشرية والضريبة الافتراضية. تغيير العملة/الدقة يغيّر العرض مستقبلًا ولا يعيد كتابة المبالغ التاريخية. المظهر يطبق فورًا على الجهاز ولا يحتاج إعادة تشغيل.

**TC-SET-001:** احفظ «بقالة النيل التجريبية» ثم أغلق التطبيق وافتحه وتحقق من بقائها وفي معاينة الإيصال. سلبي: تجاوز الأطوال/قيمة ضريبة غير صالحة يجب أن يُبقي المدخلات مع رسالة.  
**TC-SET-002:** بدّل العملة والدقة والمظهر، افتح شاشة مالية قديمة؛ يجب تغير التنسيق لا القيمة المخزنة.

### الوحدات والميزات

**الإعدادات ← الوحدات والميزات** يعرض الوحدات الاختيارية الفعلية وخصائص المنتجات المدعومة فقط. التبديل يطلب تأكيدًا ويحفظ فورًا. تعطيل ميزة يغلق تبويباتها ولا يحذف بياناتها. الوحدات الأساسية تبقى مفعلة داخليًا ولا تظهر كبطاقات تحكم. IMEI يتطلب تتبع الأرقام التسلسلية. المخزون الأساسي يفتح دليل المخازن؛ تعدد المخازن يلزم للإضافة/النقل. التصنيع والفروع المتعددة وخدمات الكاش والتقارير المتقدمة لا تُعرض لأنها لا تملك مسارات تشغيل مكتملة.

**TC-FEA-001:** افتح شاشة مشروطة، عطّل ميزتها، تحقق من اختفاء الرابط وإغلاق التبويب ورفض الرابط المباشر؛ أعد التفعيل وتأكد من عودتها وبقاء البيانات.

### المستخدمون والصلاحيات وسجل العمليات

في **المستخدمون والصلاحيات**: بحث، فلتر الدور/الحالة، **إضافة**، **تعديل**، تنشيط/تعطيل، **إعادة تعيين كلمة المرور**، ومحرر شاشات الكاشير. الأدوار مسؤول/كاشير فقط. لا يمكن تعطيل أو تخفيض آخر مسؤول نشط. تغيير الدور/الحالة/كلمة المرور يبطل جلسات الهدف. سجل العمليات إداري، يبحث ويصفّي بالتاريخ والنتيجة ويعرض المستخدم والطريقة والمسار والحالة؛ لا يحفظ body أو كلمات مرور ولا يغني عن دفاتر المال والمخزون.

**TC-USR-001:** أنشئ `cashier.test` ككاشير، امنحه POS والمبيعات فقط، سجّل دخوله وتحقق من المسموح ومن رفض الإعدادات بالرابط المباشر.  
**TC-USR-002:** عطّل الكاشير أثناء جلسة مفتوحة؛ أول طلب تالٍ يجب أن يفقد الجلسة. سلبي: جرّب تعطيل آخر مسؤول وتكرار اسم مستخدم باختلاف حالة الحروف.  
**TC-AUD-001:** نفّذ قراءة وحفظًا وفشل تحقق، ثم صفِّ سجل العمليات؛ تحقق من actor/time/status وعدم ظهور السر.

## 6. العملاء

**إدارة العملاء** توفر بحثًا وفرزًا ومراجعة الرصيد، ثم **إضافة عميل** و**تعديل**. النموذج الحقيقي يحفظ في SQLite؛ راجع الحقول الظاهرة ولا تفترض حقلًا غير موجود. الهاتف نص تعريف لا يُستخدم كحساب. **كشف حساب العميل** يختار العميل والفترة، ويعرض الرصيد الافتتاحي وحركات الزيادة/الخفض/التحصيل، مع إضافة مديونية وتحصيل. الرصيد الحالي الكامل مختلف عن رصيد إغلاق الفترة. اختيار العميل في POS يربط الآجل والحركات بالفاتورة.

**TC-CUS-001 — إضافة/تعديل:** أضف أحمد التجريبي بالكود الظاهر والهاتف `01000000001` ورصيد افتتاحي 100.00 إن أتاح النموذج، ابحث وعدّل الهاتف، ثم أعد التشغيل. المتوقع سجل واحد ورصيد ثابت. سلبي: كود مكرر/اسم فارغ.  
**TC-CUS-002 — حركة حساب:** من كشف الحساب أضف 50.00 مديونية ثم حصّل 30.00. المتوقع الرصيد +20 عن البداية، صفان مؤرخان، وإثبات التحصيل في الخزينة إن طلبت الشاشة حسابًا. أعد نفس الطلب بعد انقطاع بنفس العملية؛ لا يتكرر.  
**TC-CUS-003 — الفترة:** اختر فترة لا تشمل الحركة؛ الرصيد الحالي يبقى كاملًا بينما تفاصيل/إغلاق الفترة يعكسان الحدود.  
**TC-CUS-004 — POS آجل:** اختر العميل، أكمل فاتورة آجلة، تحقق من قائمة البيع وكشف الحساب. لا تسمح بآجل بلا عميل.

## 7. الموردون والمشتريات

**قائمة الموردين** تضيف/تعدل وتبحث. **حسابات الموردين** تجمع فواتير المورد، كشفه، مديونيته والمدفوعات. توزيع السداد يبدأ بالأقدم حسب الاستحقاق ثم تاريخ الفاتورة/الإنشاء. **إدارة المشتريات** تنشئ مسودة من مورد ومخزن وبنود كمية/وحدة/تكلفة ثم ترحّل؛ النقدي يسحب من خزينة داخل نفس المعاملة، والآجل يرفع مستحق المورد. **قائمة المشتريات** للبحث والتصفية والمراجعة. مرتجع الشراء يتم من مركز المرتجعات ويعيد الكمية للمورد ويخفض المخزون/الالتزام حسب الحالة.

**TC-SUP-001:** أضف «شركة النور التجريبية»، عدّل الهاتف، وابحث. سلبي: الحقول المطلوبة/التكرار.  
**TC-PUR-001 — شراء آجل:** اشتر 10 أرز ×20.00 للمخزن الرئيسي وآجلًا. المتوقع فاتورة منشورة 200.00، المخزون +10، طبقة FIFO 10@20، مديونية المورد +200، ولا سحب خزينة.  
**TC-PUR-002 — شراء نقدي:** اشتر 5×20 من خزينة رصيدها 500. المتوقع مخزون +5 ورصيد الخزينة 400، والفاتورة مسددة. الرصيد غير الكافي يرفض العملية كلها.  
**TC-SUP-002 — سداد:** سدّد 120.00 من خزينة. المتوقع انخفاض الخزينة والمديونية 120 وتوزيع على أقدم مستحق. تكرار مفتاح العملية لا يكرر السداد.  
**TC-PUR-003 — مرتجع:** أرجع 2 من فاتورة 20.00؛ المتوقع المخزون -2، مرتجع 40، وتخفيض المستحق/أثر الخزينة وفق تسوية الأصل. امنع إرجاع أكثر من المتبقي.  
**التحقق المشترك:** قائمة المشتريات ← تفاصيل المصدر؛ دليل المخازن ← الرصيد والحركة؛ حساب المورد؛ الخزينة؛ تقرير المشتريات/المرتجعات.

## 8. المنتجات والتصنيفات والوحدات والباركود

من **تصنيفات المنتجات** أنشئ رئيسيًا/فرعيًا وعدّل/عطّل وفق الأزرار. من **وحدات القياس** أنشئ وحدة أساسية. **دليل المنتجات** يدعم البحث والفلاتر والفرز/التصفح الظاهر، إضافة/تعديل/إضافة سريعة، تنشيط/أرشفة، والانتقال للباركود والملصقات. السعر المرجعي للشراء وسعر البيع scale-4، والمدخل المالي العام مقيد بسياسة العرض. الحفظ المتزامن محمي بإصدار؛ عند تغير السجل حدّثه بدل الكتابة فوقه.

الخصائص المدعومة: variants عامة، batch/expiry، serial/IMEI، وحدات بيع وتحويلاتها، حزم، وزن يدوي، والسماح بالبيع دون رصيد؛ ظهورها مشروط بالميزة وتعيين المنتج. لا توجد أحجام/ألوان. الهوية الفعلية للدفعة/السيريال تُسجل عند الاستلام/المخزون لا بمجرد تفعيل المفتاح.

### وحدات البيع والتسعير

الوحدة الأساسية مخزونها المشترك. إذا كان الكرتون = 12 قطعة وسعره 270، بيع كرتون واحد يخصم 12 قطعة ويحسب 270 (22.50 للقطعة ضمنيًا)، ولا يضرب سعر القطعة 25. يمكن اختيار الوحدة من بطاقة POS بالنقر الأيمن أو الضغط المطول أو الباركود المرتبط. سعر الوحدة المستقل هو المصدر؛ التحويل والدقة يراجعان وفق القيم المعروضة. تغيير السعر يدويًا يوسم السطر كتجاوز؛ **استعادة السعر التلقائي** تعيد تسعير الوحدة/الكمية. المرتجع يعيد كمية الأساس المقابلة للوحدة المباعة.

### الباركود والملصقات

إدارة الباركود من المنتج تسمح إضافة/توليد، حفظ، نسخ، تعديل، حذف بتأكيد ومعاينة. الملصقات الأصلية تحتاج ميزة `barcode-label-printing` وطابعة Windows معيّنة. الطباعة فعلية وليست browser print، وحالة `submitted_unknown/accepted` لا تثبت خروج الورق. اختبر Code 128/النوع الظاهر فقط ولا تفترض نوعًا غير معروض.

**TC-CAT-001:** أنشئ تصنيف «بقوليات» ووحدة «قطعة»، ثم منتج RICE-001 بسعر شراء 20 وبيع 25 وحد طلب 3. ابحث وعدّل وأعد التشغيل.  
**TC-CAT-002:** افتح نسختين من المنتج، احفظ الأولى ثم الثانية؛ يجب ظهور تعارض/طلب تحديث وعدم ضياع الأول.

## 9. المخازن والمخزون

**دليل المخازن** هو مركز المخازن والأرصدة والحركات: إضافة مخزن (عند تفعيل التعدد)، استلام/صرف، تسوية، جرد وتسوية، نقل، وعكس حركة حيث تسمح الواجهة. الكميات الدقيقة scale-6. كل حركة لها مصدر ولا تُعدّل الرصيد مباشرة. FIFO يستهلك الأقدم، والتحويل بين المخازن ينقل الكمية وتكلفتها، والجرد يسجل الفرق. المنتجات ذات batch/serial/IMEI تتطلب الهويات المناسبة. بيع منتج يمنع العجز إلا إذا كان `AllowSaleWhenOutOfStock` مفعّلًا؛ عند السماح تبقى كمية الفاتورة كاملة ويُستهلك المتاح فقط، وهو فرق يجب إبرازه في الاختبار.

**TC-INV-001:** أضف مخزنًا «فرع الاختبار»، عطّله/فعّله وتحقق من الاختيار. لا يمكن استخدام مخزن غير نشط.  
**TC-INV-002:** استلم 10@20 ثم 5@22؛ بع 12. المتوقع رصيد 3، تكلفة FIFO `10×20 + 2×22 = 244`، والطبقة الباقية 3@22.  
**TC-INV-003:** انقل 2 من الرئيسي للفرع؛ المصدر -2 والهدف +2 وصافي المنشأة ثابت مع حركة مترابطة. العكس/التكرار لا يكرر الحركة.  
**TC-INV-004:** عد فعليًا 4 بينما الدفتري 3؛ التسوية +1 مع سبب. سلبي: كمية/هوية غير صالحة.  
**TC-INV-005:** منتج دون رصيد: مع المنع ترفض الفاتورة كاملة؛ مع السماح تُنشر ولا يصبح مخزون فعلي وهمي سالبًا بحسب العقد الحالي، ودوّن العرض الفعلي.  
**TC-INV-006:** دفعة صلاحيتها قريبة وسيريال مكرر وIMEI؛ تحقق من رفض التكرار وظهور تنبيه الصلاحية واختفاء الدفعة عند صفر المتبقي.

## 10. الكاشير والمبيعات والمرتجعات والتوصيل

**TC-SAL-003:** صحح/ألغِ فاتورة مسموحًا بها وتحقق من حركة عكسية لا حذف التاريخ، واستعادة المخزون/الخزينة مرة واحدة.

## 11. الخزينة والمصروفات ووسائل الدفع والأقساط

### الخزينة والبنك

**قائمة الخزنة والبنك**: **+ إضافة خزنة أو بنك**، كود، اسم، نوع، ملاحظات؛ تعديل وحذف. الحساب يبدأ بصفر ولا يُحذف إن له حركات. **إيداع رصيد/سحب رصيد** يختاران الحساب والمبلغ والبيان؛ عند نتيجة شبكة غير مؤكدة أعد نفس الطلب للتحقق بدل بدء عملية جديدة. الإيصال يعرض رقم الحركة والرصيد بعدها.

**TC-TRY-001:** أنشئ CASH-TEST، أودع 1000 واسحب 125.50؛ الرصيد 874.50 والحركتان في السجل. المبلغ صفر/سالب/سحب أكبر من الرصيد مرفوض. حذف الحساب ذي الحركة مرفوض.  
**TC-TRY-002:** اقطع العرض بعد الإرسال وأعد المحاولة بنفس البيانات؛ يجب replay بلا حركة مزدوجة.

### المصروفات

**إدارة المصروفات** تدير التصنيفات المحفوظة، و**سند صرف** يختار تصنيفًا وخزينة ومبلغًا وتاريخًا/بيانًا ثم يرحّل؛ السحب وسند المصروف في معاملة واحدة. تقرير المصروفات يقرأ السندات، وصافي الربح يضم المصروفات المصنفة حسب السياسة.

**TC-EXP-001:** أضف «كهرباء»، رحّل 150 من CASH-TEST؛ الخزينة -150، سند واحد، التقرير +150 مصروف. فشل الرصيد يجب ألا يترك سندًا.

### المحافظ والفيزا

الشاشات الأربع إدارية: نظرة عامة، محافظ، ماكينات فيزا، سجل العمليات. أضف/عدل/فعّل الوسيلة ثم استخدمها في فاتورة كاملة؛ الاسم الحالي يظهر في التقارير لكن هوية الدفع المحفوظة ثابتة. الأرقام ليست أرصدة بنكية فعلية.

**TC-PAY-001:** أضف محفظة «فودافون تجريبي» ورقمًا وهميًا وجهاز «POS-TEST»، نفّذ بيعًا بكل منهما، ثم صفِّ السجل والتقرير. تعطيل الوسيلة يمنع الجديد ولا يمحو التاريخ.

### التقسيط

المساران `installment-system` و`installment-payment` معلَّمان implemented لكن وصف السجل يقول صراحة «محسوب داخل الجلسة/محاكاة السداد»، بينما backend يحوي خدمة تقسيط محفوظة وتقارير/تنبيهات. لذلك هذه نقطة **يحتاج تحقق أثناء التجربة اليدوية**: أثبت من الواجهة هل العقد والسداد يبلغان API ويستمران بعد إعادة التشغيل قبل اعتباره حسابًا حقيقيًا.

**TC-INS-001:** أنشئ عقدًا لعميل بقيمة 1200، مقدم 200، خمس دفعات 200، تواريخ متتابعة. التوقع الحسابي: مديونية 1000 وجدول 5×200. أعد التشغيل وافتح التقرير/الكشف/التنبيه؛ إن اختفى، سجله كحد جلسة لا كعيب افتراضي.  
**TC-INS-002:** سدّد قسطًا جزئيًا/كاملًا، تحقق من المتبقي وعدم قبول تجاوز المجدول أو تكرار العملية.

## 12. الموظفون والحضور والرواتب والورديات والصيانة

**إضافة وإدارة الموظفين** يحفظ الموظف ولا ينشئ حساب دخول، والحذف أرشفة. **السلفيات** تسحب من الخزينة. **صرف الرواتب** يحسب صافي الشهر بعد السلف غير المخصصة، يمنع تكرار موظف/شهر، ويسحب ذريًا من الخزينة. الحضور اختياري مستقل عن وردية الكاشير، وله دخول/خروج وتصحيح إداري وسجل.

**TC-WRK-001:** أضف موظفًا براتب 3000، سلفة 500، اصرف الشهر؛ المتوقع صافي 2500 وتخصيص السلفة مرة واحدة وخزينة -3000 إجمالًا للحركتين. تكرار الشهر مرفوض.  
**TC-ATT-001:** حضور ثم خروج واستعراض السجل؛ خروج بلا حضور/حضور مزدوج مرفوض، والتصحيح يظهر كتصحيح لا محو.

الورديات: F10 أو **الوردية الحالية**؛ أدخل نقد افتتاحي، نفّذ المبيعات، ثم الإغلاق بعد عد النقد. المتوقع النظري `افتتاحي + حركات نقدية الداخلة - الخارجة` وفق الحركات المرتبطة؛ البطاقة/المحفظة والآجل لا تدخل النقد. **تفاصيل الوردية** تعرض المراجع، و**تقارير الورديات** الفروق.

**TC-SHF-001:** افتح 100، بيع نقدي 50 وبطاقة 40، أغلق بعد عد 150؛ المتوقع فرق صفر والنقد المتوقع 150. أغلق على 145 في تجربة أخرى؛ فرق -5. لا تفتح ورديتين للمستخدم نفسه.

الصيانة: **تسجيل جهاز للصيانة** يحفظ العميل والجهاز والعطل والاستلام والتسليم المتوقع والمقدم. المقدم عند الاستلام ليس حركة عميل/خزينة في تلك اللحظة. **قائمة الصيانة** تغيّر الحالة وتسجل التسليم؛ عند التسليم تُرحّل تكلفة الخدمة، تخصم المقدم، وتحصّل الباقي إلى خزينة مختارة في معاملة واحدة.

**TC-MNT-001:** جهاز صيانة 500 ومقدم 100؛ تحقق أن الاستلام لا يحرك الخزينة/كشف العميل، ثم سلّم بتحصيل 400 إلى CASH-TEST؛ المتوقع حركة تحصيل 400 وتسوية تكلفة 500 دون تكرار المقدم.

## 13. التقارير والتنبيهات والتصدير

التقارير المنفذة: المبيعات، المشتريات، المرتجعات، وسائل الدفع، المصروفات، صافي الربح، أرباح المنتجات، تقييم المخزون، الأكثر مبيعًا، نواقص المخزون، حركة المخزون، العملاء، الموردين، الورديات، الحضور، الصيانة، التقسيط، وملخص النشاط. الفلاتر من الخادم وتشمل الفترة والبحث ونوع/حالة/تصنيف/مخزن حيث يظهر. الأرقام تقرأ المستندات المحفوظة ولا تعيد الترحيل. صافي الربح = ربح المبيعات المحقق بعد تخصيص المرتجعات ناقص المصروفات الداخلة في التصنيف؛ أي تغطية ناقصة تظهر كتحذير/null ولا تُخمن.

**TC-RPT-001:** أنشئ شراء 10@20، بيع 4@25، بلا ضريبة/خصم، مصروف 10. الربح الإجمالي المتوقع 20، والصافي 10؛ المخزون 6 وتقييم FIFO 120. طابق كل رقم مع المصدر.  
**TC-RPT-002:** طبّق فترة تستبعد إحدى الحركات، ثم reset؛ تحقق من الملخص والجدول معًا، ومن paging/sort إن ظهرا.  
**TC-RPT-003:** قارن أعلى المنتجات ونواقص المخزون وحركة المنتج بالمخزون الفعلي؛ لا تُظهر تقارير الأرباح لمستخدم بلا صلاحية مالية.

التنبيهات الفعلية: حد الطلب (`threshold>0 && total<=threshold`)، نفاد/نقص عند الصفر أو السالب، دفعات الصلاحية ذات المتبقي، وأقساط غير مدفوعة. الإجمالي عبر كل المخازن. **مقروء/غير مقروء** لكل مستخدم ويستمر بعد إعادة التشغيل؛ **تعليم الكل كمقروء** يخفض الشارة ولا يحذف التنبيه. لا polling دائم؛ التحديث عند الكتابة/التركيز/زر **تحديث**.

**TC-ALT-001:** اجعل الحد 3 والرصيد 3 ثم 0، تحقق من نوع التنبيه والشارة، علّمه مقروءًا وأعد التشغيل. ارفع الرصيد فوق 3 فيختفي التنبيه الحالي.

### Excel/CSV

التصدير يتم من أزرار **تصدير** الموجودة في الشاشات الداعمة، ثم اختيار XLSX أو CSV وحوار Windows **حفظ باسم**. المصدر server-side ويفترض تطبيق الفلاتر الحالية حسب dataset. لا تعتبر المسار القديم `customers-export` دعمًا؛ هو «قيد الإنشاء». افحص اسم الأعمدة وترميز العربية والقيم والتواريخ وعدد الصفوف. الحفظ إلى USB يعتمد على صلاحية Windows ومساحته.

**TC-EXPOR-001:** صفِّ dataset منفذًا إلى صفين، صدّر XLSX ثم CSV إلى مجلد مؤقت/USB، افتح الملفين وتحقق من الأعمدة والعربية وصفين فقط وعدم وجود كلمة مرور/hash. ألغِ الحوار؛ لا ملف ولا رسالة نجاح كاذبة.

## 14. الطباعة والأجهزة والموازين

في **الطابعات والطباعة**: تحديث قائمة Windows، إضافة/تعديل طابعة (اسم داخلي، طابعة Windows، مقاس الورق)، تعيينها لنوع مستند، إعداد القالب والهوامش والشعار PNG حتى 130KB، معاينة، حفظ، اختبار، إزالة، وسجل المهام/**مراجعة بعد 10 دقائق**. الطابعة المضافة مرتين مرفوضة؛ إزالة المعيّنة تلغي التعيين والطباعة التلقائية ذات الصلة بعد تأكيد واضح. المعاينة بيانات اختبار ولا تطبع.

**TC-PRN-001:** أضف طابعة مثبتة، عيّنها للبيع، عاين 58/80mm، احفظ ثم اطبع اختبارًا وفاتورة. افصل الطابعة وكرر؛ يجب ظهور تشخيص وعدم تكرار الفاتورة. تحقق يدويًا من RTL والقص.  
**TC-PRN-002:** ارفع JPG أو PNG أكبر من 130KB، وطابعة Windows غير موجودة، وتكرار نفس الطابعة؛ كلها مرفوضة مع بقاء النموذج.

**إعداد الموازين** يحفظ profile باركود الميزان وربط PLU/SKU. اختبر بادئة وطول وحقل وزن/سعر حسب الحقول الفعلية؛ باركود الوزن اليدوي يضيف الكمية/الوزن المستخرج. لا تفترض بروتوكول ميزان مباشر؛ المدعوم هو تحليل الباركود المكوّن.

**TC-SCL-001:** احفظ profile تجريبي واربط PLU بالمنتج، امسح باركود وزن معروف واحسب الكمية والسعر المتوقعين من أرقام الحقل. باركود قصير/بادئة خاطئة/PLU مجهول مرفوض بلا سطر.

## 15. النسخ الاحتياطي والاستعادة

من **البيانات والصيانة** راجع صحة القاعدة والمسار. النسخة اليدوية ZIP تحتوي manifest وقاعدة ملتقطة Online Backup، تفحص integrity/foreign keys وSHA-256، لكنها **غير مشفرة** وتحتوي سجلات العمل وpassword hashes؛ احمها. لا تحتوي TrialState/Sessions/ترخيص/DPAPI/Registry. النسخ التلقائي معطل افتراضيًا، يعمل أول فرصة يومية محلية، يعيد المحاولة بعد 5 دقائق على الأقل، ويحتفظ بآخر 7 نسخ تلقائية في المجلد الحالي؛ اليدوية لا تُحذف.

الاستعادة: **معاينة** الملف، تحقق التاريخ/الإصدار/migration، تأكيد استبدال البيانات صالح 10 دقائق، يدخل الخادم صيانة، ينشئ `RestoreRecovery`، يستبدل القاعدة ذريًا، يفرغ Sessions ويطلب دخول مستخدم من النسخة. schema غير مطابق/نسخة أحدث تُرفض قبل التغيير. الترخيص والتجربة المحلية لا يتغيران.

**TC-BAK-001:** أنشئ نسخة يدوية إلى مجلد مؤقت، تحقق من التاريخ والحجم والسجل، ثم افحصها بالمعاينة. ملف تالف/ZIP آخر يجب رفضه.  
**TC-BAK-002:** فعّل يوميًّا بمجلد قابل للكتابة، تحقق من آخر نجاح/فشل والاحتفاظ؛ مجلد غير قابل للكتابة يظهر فشلًا ولا يمنع تعطيل الجدولة.  
**TC-BAK-003 — قاعدة disposable فقط:** انسخ، أضف عميلًا مميزًا، استعد النسخة بعد التأكيد؛ العميل يختفي، البيانات الأقدم تعود، الجلسة تنتهي، والترخيص يبقى. افحص Recovery. لا تنفذ على قاعدة تشغيل.

## 16. الرحلات المترابطة

**JNY-01 — إعداد بقالة صغيرة:** تفعيل/مسؤول → بيانات المنشأة → الميزات → مخزن → وحدة/تصنيف → المورد/العميل → المنتج/الباركود → مخزون افتتاحي/شراء → وردية → بيع نقدي → طباعة → تحقق من المخزون والخزينة والتقارير → إعادة تشغيل. استخدم RICE-001 والأرقام السابقة.  
**JNY-02 — شراء ← مخزون ← بيع ← ربح:** شراء 10@20 آجل، بيع 4@25 نقدًا، مصروف 10. النتائج: مخزون 6، مورد 200 قبل السداد، نقد البيع 100 ناقص المصروف بحسب الحساب، إجمالي ربح 20، صافي 10.  
**JNY-03 — المرتجعات والتسوية:** بيع 5×25، أرجع 2 ثم 1؛ المخزون يرجع 3، إجمالي الرد 75 بلا ضريبة/خصم، المتبقي القابل 2. طابق الخزينة/الكشف.  
**JNY-04 — متعدد الوحدات:** قطعة 25 وكرتون 12 بسعر 270؛ بع قطعة+كرتون =295 واستهلاك 13. تجاوز الكرتون 260 ثم استعد 270، وأرجع الكرتون فيعود 12.  
**JNY-05 — آجل وتقسيط:** بيع آجل حقيقي لعميل وتحقق من كشفه؛ ثم نفّذ TC-INS-001 وافصل بوضوح هل استمر العقد أم كان جلسة.  
**JNY-06 — الوردية:** افتتاح 100، نقد 50، بطاقة 40، مصروف نقدي مرتبط إن كانت الشاشة تربطه بالوردية، إغلاق وعد ومقارنة كل مرجع.  
**JNY-07 — الصلاحيات:** مسؤول ينشئ كاشير POS فقط؛ اختبر القائمة والبحث والرابط المباشر والـAPI عبر الواجهة، ثم التعطيل الفوري.  
**JNY-08 — النسخ والاستعادة:** نفذ TC-BAK-003 على disposable وسجّل hashes/وقت النسخة والدخول بعد الاستعادة.  
**JNY-09 — التقارير والتصدير:** أنشئ dataset معروفًا، طابق المصادر، فلتر، XLSX/CSV، طباعة تقرير إن ظهر زر فعلي.  
**JNY-10 — الاستمرار بعد restart:** بعد كل الإعدادات والمعاملات أغلق طبيعيًا وافتح وسجّل الدخول؛ تحقق من المنشأة والمستخدمين والمنتجات والمخزون والفواتير والخزينة والقراءات. استثناءات محلية: المظهر/طي القائمة على الجهاز، والجلسة قد تستمر حتى 8 ساعات ما لم تبطل.  
**JNY-11 — الموظف والراتب:** موظف → حضور → سلفة → راتب → خزينة → تقارير موظفين، مع منع التكرار.  
**JNY-12 — الصيانة:** استلام جهاز ومقدم → حالات → تسليم وتحصيل → كشف عميل وخزينة وتقرير.

## 17. اختبارات الخطأ والحواف العامة

- انقر حفظ/ترحيل مرتين، وأعد الطلب بعد انقطاع: لا تكرار مالي/مخزني.
- استخدم صفرًا وسالبًا وأقصى طول وفواصل عربية/إنجليزية ومنازل عشرية زائدة.
- افتح نفس السجل بحسابين واحفظ بالتتابع: يجب تعارض إصدار لا overwrite صامت.
- عطّل مستخدمًا/ميزة/وسيلة/مخزنًا/منتجًا وهو مفتوح، ثم حاول الحفظ.
- اختبر قاعدة فارغة، صفحة أخيرة فارغة، بحثًا عربيًا بهمزة/مسافة، ونصًا عربيًا طويلًا.
- افصل الطابعة، امتلاء القرص، مجلد read-only، ملف backup تالف، وفقد الخادم؛ لا رسالة نجاح كاذبة.
- قارن كل مبلغ بثلاثة أماكن: مستند المصدر، دفتر الطرف/الخزينة، التقرير. وقارن كل كمية بالمستند والحركة والرصيد.
- اختبر الوقت حول منتصف الليل والفترة الشاملة؛ التخزين UTC والعرض محلي.

## 21. خلاصة التغطية والحدود المفتوحة

### التشغيلات والصلاحية في الشراء والاستلام

- في **إدارة المشتريات** تظهر **رقم التشغيلة** لكل منتج يتتبع التشغيلات، وتظهر **تاريخ الصلاحية** لكل منتج يتتبع الصلاحية. كلاهما مرتبط ببند الفاتورة نفسه ويبقى عند تعديل الكمية والوحدة والأسعار والمورد والمخزن.
- زر **إنشاء رقم تشغيلة داخلي** اختياري ويولّد هوية تبدأ بـ `INT-`؛ لا يدّعي أنها رقم الشركة المصنّعة. يمكن استبدالها قبل الحفظ برقم المصنع الفعلي.
- عند النشر تُحفظ الفاتورة وأثر المورد وحركة الاستلام والتكلفة والتشغيلة في معاملة واحدة. رفض بيانات التتبع لا يترك فاتورة منشورة أو حركة مخزون أو رصيد مورد جزئيًا.
- في **دليل المخازن ← استلام بضاعة** تُقرأ إعدادات المنتج الفعلية وتظهر حقول التشغيلة والصلاحية والسيريال/IMEI المطلوبة. هذا استلام مخزني فقط ولا ينشئ فاتورة أو دين مورد.
- هوية التشغيلة مستقلة حسب المنتج/المتغير، ويمكن للمنتج امتلاك تشغيلات عديدة بتواريخ مختلفة. الرصيد الإجمالي هو مجموعها، مع بقاء كمية كل تشغيلة ومخزن مستقلة.
- تعتمد **التنبيهات** على `InventoryBalances` و`ProductBatches`: صف واحد لكل تشغيلة ومخزن ذي رصيد موجب داخل نافذة التحذير. يعرض الصف المنتج والتشغيلة والمخزن والتاريخ والكمية والشدة. الاستهلاك الجزئي يخفض الكمية، والاستهلاك الكامل يزيل التنبيه، والنقل ينقل الكمية والتنبيه بين المخزنين وفق الحركة المحفوظة.

- إجمالي المسارات المسجلة: **131**.
- `implemented: true`: **82** (منها تحويلات توافقية معلَّمة منفذة، ولذلك لا تساوي 82 شاشة مستقلة).
- `implemented: false`: **49**؛ التحويلات القديمة **38**، و`under-construction` **2**، والباقي نماذج/تقارير/إعدادات غير منفذة.
- المسارات الإدارية: **34**؛ المشروطة بميزة: **41**.
- كل مسار في المصفوفة له تحقق يدوي؛ كل شاشة منفذة مرتبطة بعائلة سيناريو واحدة على الأقل.
- يحتاج تحقق بشري خاص: استمرارية واجهة التقسيط، كل تفاعل long-press على جهاز لمس، جودة/حالة الطباعة الفعلية، الماسح والميزان، WebView2/Windows 7 Chromium 109، وحوار Save File.
- نقاط لا تُعامل كعيوب مؤكدة: المسارات المؤجلة، حدود الجلسة المعلنة، وأي زر يعتمد جهازًا غير متصل. سجّل العيب فقط بعد تنفيذ السيناريو ومقارنة النتيجة بالعقد أعلاه.
