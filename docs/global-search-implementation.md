# Global Search implementation

The original Header searched the authorized screen registry and quick actions. The historical screenshot and audit index show this screen-only dropdown. The working tree at continuation contained a Header prototype that also queried the catalog and sales APIs. Settings still filtered its own cards by title and description.

Both inputs now mount the same service in `frontend/js/services/global-search.js`. The Settings cards are still generated by `settings-hub.js`. `app.js` supplies the registry, feature and permission checks, existing icons, and workspace navigation. Settings destinations receive a deterministic priority in Settings. Both inputs receive the same record groups. Aliases lead to existing screens, including the printing screen that contains the receipt designer.

The service accepts a typed result with a positive safe integer ID, a fixed provider route, and minimal display metadata. It resolves navigation through a provider allowlist. Purchase, sales, return, and shift results use existing detail state. Product and contact results show the selected identity inside their existing directories. Delivery uses the invoice ID against the current posted delivery set. Driver, payment instrument, expense, maintenance, installment, and workforce results use the contextual lookups described in the coverage table. Selecting a result performs reads and navigation.

Each input owns its own selection and request generation. The service debounces for 300 ms, deduplicates simultaneous reads for the same query and authorized provider set, and keeps no settled result cache. Closing an input, replacing its query, changing workspace tabs, or invalidating effective access prevents stale rendering. Search reads are excluded from the shell's page freshness snapshots. The popup shows up to five rows per provider and ten navigation results. The normal list screens remain available for broader inspection.

Navigation text uses the existing Arabic normalization. Numeric-only record lookups convert Arabic and Eastern Arabic digits to Western digits and retain leading zeros. Other record query text is trimmed and keeps its original spelling and punctuation. SQL comparisons follow each source's existing rules. Product lookup applies exact barcode and SKU ranking before the page limit. Purchase, sale, return, expense, and installment lookups prioritize exact references where the store supports it.

## Source changes

- Header integration and Settings mount: `frontend/index.html`, `frontend/js/app.js`, `frontend/css/layout.css`, `frontend/js/modules/settings-hub.js`, and the shared service.
- Contextual reads: `catalog.js`, `delivery.js`, `expenses.js`, `inventory.js`, `payment-methods.js`, `renderers.js`, `treasury.js`, and `workforce.js` in `frontend/js/modules`.
- New read routes and optional filters in the Catalog, Customers, Delivery, Expenses, Maintenance, Payment Methods, Purchases, Returns, Sales, Suppliers, and Treasury controllers. Their Application and Data counterparts validate and execute bounded, parameterized reads. Workforce reuses its existing controller and adds a shift search predicate to the read store.
- Tests: `frontend/tests/global-search-tests.js`, `frontend/tests/global-search-browser.cjs`, the frontend suite runner, and `tests/AlKhayal.IntegrationTests/GlobalSearchApiTests.cs`.

The shared service checks destination access before requesting or opening results. Backend handlers retain session, screen, module, administrator, and owner checks where applicable. New contact directory reads require the exact directory grant and project identity fields only. The original contact lookups used by operational flows keep their earlier contracts. The data changes are bounded reads against the existing schema. No schema migration is required.

See [coverage](global-search-coverage.md) for the provider inventory and [QA](global-search-qa.md) for measured behavior and test limits.
