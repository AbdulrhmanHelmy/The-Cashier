# Final stage defect register

November 21, 2026. Evidence uses disposable records. See the [original audit](../THE_CASHIER_UI_UX_AUDIT.md), [screenshot index](../THE_CASHIER_UI_SCREENSHOT_INDEX.md), and [current test evidence](../artifacts/final-stage/).

| ID and severity | Screen and classification | Reproduction, expected and observed behavior | Root cause, correction and final status |
| --- | --- | --- | --- |
| FINAL-01 · P1 | Delivery Orders → Sales invoice · REPRODUCED | Open an order's linked invoice, hold the invoice GET, switch tabs, release the GET and return. The expected invoice editor should open for the selected invoice. Before the fix, the response arrived but the view stayed blank. | The invoice handler discarded responses when its view was inactive, although the workspace retained the view. The loading identity could remain set. `sales.js` now accepts responses for the current retained view and rejects invalidated views and superseded requests. Fixed for the reproduced case. [Before](../artifacts/final-stage/1024x768-light-invoice-load-before.png) · [After](../artifacts/final-stage/1024x768-dark-delivery-editor.png) |
| FINAL-02 · P2 | Delivery editor in POS and Sales · NEW DEFECT | Open a correctable invoice whose saved driver is absent from the active driver list. The expected editor should identify the assignment and require a deliberate change. The first selectable item previously represented an unassigned order and could silently clear the saved driver on save. | The picker rendered only current active choices plus the empty value. `sales.js` preserves the displayed saved identity and asks for explicit reassignment or removal. It also checks the request, invoice, customer and cart context at response and action time. Current Edge regression verifies the displayed ID and guards Save. API coverage confirms the existing inactive-driver rejection. |
| FINAL-03 · P2 | Driver create/edit · REPRODUCED | Submit a driver, hold the request, press Escape and return a rejection. The operator should see the rejection and be able to correct the original inputs. Escape previously discarded the dialog before the response. | Only the Save button was disabled. `delivery.js` guards duplicate submission and dismissal, freezes fields while saving and restores the same dialog on rejection. Fixed in Edge. [Pending save](../artifacts/final-stage/1024x768-dark-driver-saving.png) |
| FINAL-04 · P1 | Touch POS and Sales checkout · REPRODUCED | Interrupt the response after the post request has been sent. The UI should report that the result is uncertain and identify the saved invoice. The original warning invited retry under the generic failure treatment. | Posting and display failures shared a generic error path. `sales.js` now distinguishes uncertain posting and a known confirmation with a display failure. The simulated transport failure in `payment-methods-tests.js` checks no automatic submission, invoice number in the warning, and same-key recovery on explicit action. Fixed for the simulated response loss. |
| FINAL-05 · Historical | POS completion and cancellation · ALREADY FIXED | The audit observed brief checkout success and insufficient contrast for the cancellation action. Current completion includes the server-confirmed number, total, tender, View and next-sale actions, with a Print action when printing is loaded. The cancellation modal uses danger styling and validates a reason inline. | Earlier design-stage implementation. Retained. Checkout result and interrupted recovery covered by frontend assertions. Populated native cancellation remains unverified. |
| FINAL-06 · P1 investigation | Owner-reported intermittent delivery creation/edit failure · NOT REPRODUCED in the repeated live run | The owner's production-like pattern remains uncorrelated with a particular request, invoice ID, role, status or console error. The synthetic tab-switch regression reproduces one way to get a stuck invoice. Live Edge completed 20 out of 20 POS checkout → delivery edit → save → reopen trials. A separate API test ran 20 posted-order corrections and reopened each revision after a host restart. | The original incident's root cause remains unconfirmed. Posted corrections require the original open shift and current revision. Linked returns, installments and superseded invoices can produce legitimate restrictions. A denied driver lookup is a separate API contract. Delivery acceptance stays partial pending native and incident-specific verification. [Trial log](../artifacts/final-stage/edge-live-delivery.txt) · [Release blockers](final-release-blockers.md) |
| FINAL-07 · Existing policy | Sales cancellation · BLOCKED for cash reversal | Submit a valid reason for a posted cash invoice. The backend returns HTTP 409 `cash_refund_policy`, the editor shows the Arabic explanation inline, and the invoice remains posted. The equivalent action succeeded for a disposable unpaid credit invoice. | The cash reversal path requires an approved refund policy. **BLOCKED — REQUIRES SEPARATE BUSINESS LOGIC AUTHORIZATION** if cash cancellation is required for release. The action continues to show the existing API result. [Live checks](../artifacts/final-stage/edge-live-sales-final.txt) |
