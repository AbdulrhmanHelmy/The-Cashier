# Printing Settings UI and UX review

| Component and source | Dependencies and interaction | Finding and minimal improvement |
| --- | --- | --- |
| Managed page toolbar · printing.js | Document type and designer, Add, Windows refresh, saved reload; app shell also has data refresh | Different meanings for three refresh entry points are easy to miss. Group app profiles and Windows status in place; keep a single Add in the same visible context. |
| App printer cards · printing.js | Persisted printers, associated templates, assignment links; Windows list marks presence. Edit, preview, test and remove. Remove confirms affected links; PUT settings saves changes. | Empty text correctly says no app profiles. It does not give the Windows count or clearly distinguish a successful zero-device result. Matching by name means installed presence, with actual device condition qualified in existing copy. Failed discovery currently makes a saved card look absent. |
| Document assignments · printing.js | Sales invoice, delivery receipt, sales and purchase returns, purchase invoice, supplier payment, customer receipt, shift summary and shift closing. App-printer ID, legacy printer name fallback, per-document designer, automatic sale/delivery and PUT settings. | Preserve all nine mappings, copy and template semantics and old configurations. Programmatically associate each select with its document name. Retain current explanatory distinction from the Windows default. Show dirty/saving feedback and offer deliberate discard on saved reload. |
| Add/Edit · printing.js, shared modal | Profile name, Windows device, paper preset and dimensions, driver-supported fit controls, margins/scale/continuous options, company branding, custom PNG/remove, header/footer, receipt reference barcode and section styling. Preview through print endpoints; save uses PUT settings. | 1024×768 screenshot shows four fields across, height alone on the second row and long stacked branding; footer remains visible. Missing-paper feedback reproduced. Keep existing modal. Group device and paper, collapse optional branding/typography by default when usable, and direct focus to the invalid field. A document reference barcode exists; this audit found no QR toggle here. |
| Visual document designer · printing.js | Preset-specific controls, section typography/visibility, branding, logo, SKU where applicable, barcode, test, reset and save. Sample POST preview/branding; saved document GET documents and POST preview/document. | Existing 50–150% viewing control and sample/actual distinction are valuable. At 1024×768 the stacked layout places the preview below the editing blocks, requiring a long scroll from the top. Debounce, sequence checks, dirty-close prompt and stale-preview indication exist. Keep these. Offer a fit view and one bounded preview scroll area if populated long receipts are demonstrably hard to inspect. Verify result navigation and focus with keyboard. |
| Profile receipt preview · printing.js | Draft branding and paper, sample or saved document, sequence and file-read token; native endpoint PNG, output only after explicit test action | Historical 533–535 show preview scroll cropping. Current browser sample uses a native-generated synthetic PNG fixture where available. Saved sales, saved purchases and pagination fidelity need live qualification. Native API describes first-page preview, so a viewport fix cannot expose pages the endpoint never returns. |
| Barcode assignment and designer · labels.js | GET labels/settings after outer draw; saved device, 35×25/40×30/50×30/60×40 mm and custom dimensions, default template, preview/design and assignment/design saves | Independent label subsection should start early. Provide explicit loading, retry and neutral saved-device status. In RTL the mixed Latin unit and numerals visually reorder in the stock option; isolate the dimension text so its width × height order stays clear. A Windows refresh currently remounts the section and can lose paper/design edits. Preserve version checking, Windows paper match and product-label preview behavior. No new designer is required. |
| Advanced editor · printing.js | On expansion GET saved/defaults and another discovery. Legacy printer, default template, copies, capabilities, preset/custom margins, logo and section order, sample preview, template create/copy/delete/reset, validation/test and history. | Keep legacy compatibility and expert affordances. Share the discovery result within the screen. Keep advanced expansion and unsaved inputs through refresh. |
| Print history · printing.js | GET jobs on request, references/printer/status/message and authorized review operation; latest 100 | Lazy load is appropriate. Preserve history/confirmation and retain the expanded list on device refresh. Keep actual test-print controls distinct from preview. |

Stage 3 documented saved-product native label preview and sample design preview, with exact mixed batch layout outside that contract. The current frontend regression suite covered product preview, label dimensions, assignments and replay. No device changes or jobs were used in this review. Native focus, real saved sales/purchase image verification, fine-grained contrast and production sizing remain open.
