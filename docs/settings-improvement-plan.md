## Verification before acceptance

- Measure navigation dispatch, first visible shell, controls-ready and discovery-ready across at least five warm and five fresh-process trials. Record saved settings, company and label endpoints separately, plus Windows enumeration, active paper, status and paper definitions. Define targets against operator hardware after the baseline run.
- Use deterministic blocked/disordered responses and recording backends for zero, one, multiple, virtual, unavailable default, offline, shared/network, slow and failing Windows lists. Also test permission denial, saved-settings failure, company branding failure, manual refresh, reloading saved, close/reopen, switching away and returning before completion. Check request counts and stale responses.
- Verify saved legacy and registered selections, all nine document mappings, automatic switches, label stock and existing drafts through loading, failure and retry. Confirm expected server validation against synthetic fixtures. Cover Preview and Test as separate flows with recording backends.
- Compare sample and saved sale/purchase previews, long Arabic LTR/RTL mixtures, branding, logo, totals and footer. Exercise barcode saved layout and product preview, stale images, paper override and Stage 3 suite.
- Verify Stage C company/general pending save and cancel, stale permissions, backup external destination messaging, three viewports, both themes, focus restoration, dialog overflow and host DPI. Run frontend registry and unit tests, integration tests on isolated data, Desktop Release build and WinForms/WebView2 smoke on available hosts. Windows 7/Chromium 109 remains a separate legacy qualification.
